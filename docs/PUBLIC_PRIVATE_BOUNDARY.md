# Public and private boundary

Status: established before scoring implementation. Applies to every file, fixture, dependency integration, output, log, and Git commit in this fresh public project.

## Authority and scope

Build an independent, deliberately limited, brand-agnostic Universal Site Score. Confidential reference documents are background only and must never enter this repository or its history. Public Lite precedes any private system. It must not be extracted from private methodology, coefficients, examples, or history.

## PUBLIC APPROVED

The following capabilities are approved in scope, subject to implementation and publication quality gates:

| Capability | Allowed public implementation | Required constraint |
| --- | --- | --- |
| Address intake and geocoding | Generic address validation and replaceable geocoder | No private candidate fixtures; handle ambiguity explicitly |
| Public context adapters | Lawfully usable aggregate geographic context and generic POI normalization | Verify source terms, provenance, dates, geographic coverage, and display rights before use |
| Universal scoring | Independently authored, transparent, deliberately simple rubric | No private-derived weights, thresholds, features, or validation cases; document limitations |
| Missing data | Explicit unavailable values and assessment withholding where needed | Never invent replacement signals or treat unknown as zero |
| Explanations | Limited dimension-level descriptions of observed public inputs | No lease recommendation, revenue forecast, or brand fit |
| Interface and API | Generic forms, results, error handling, geographic utilities | No private economics fields or sensitive uploads |
| Reproducibility | Public rubric version and approved input snapshots | Do not persist confidential user inputs or call this a private model registry |
| Tests and demonstration | Independently created synthetic fixtures | Mark synthetic results prominently; never imply retrieved real-world data |
| Research | Sourced public descriptions of industry architecture | No unsupported equivalence claims or reconstruction of private methods |
| Publication controls | Secret, identifier, path, dataset and forbidden-term checks | Scan all publishable content and Git history; never embed confidential denylist examples as plaintext |

## PRIVATE RESERVED

Brand-specific decision systems; private financial gates and forecasting; proprietary feature engineering, weights and decision thresholds; evidence-confidence scoring; specialized traffic and anchor relationships; operating-role and brand-fit logic; private historical comparisons; calibration, learning, outcome ingestion and proprietary model governance. These categories are exclusion boundaries, not public implementation specifications. Do not document their calculation details.

Uncertain features default to PRIVATE RESERVED. A material capability must be added to this classification table before implementation, with an independently justified public design recorded in an ADR.

## PROHIBITED FROM PUBLICATION

Customer identities and identifiers, confidential addresses, leases, rents, sales, POS, operating economics, expansion plans, private decisions and outcomes, private conversations, credentials, tokens, internal endpoints, personal filesystem paths, private datasets, supplied confidential reference files, and anything derived from confidential customer methodology or results.

Do not copy supplied instructions or source documents into this repository. Do not import any private Git history. Never use private cases as public test fixtures, even after removing names.

## Release enforcement

Before every public push or release: classify changed capabilities; review all tracked files and generated assets; run publication and secret checks; inspect history; verify fixture origins and provider rights; run required tests; document unresolved limitations. Automated scanning supplements human judgment and cannot prove absence of all sensitive content. A failed gate blocks publication.

Public-facing results must say that the assessment is universal and informational, based on available approved data, not a guaranteed revenue forecast, not a substitute for lease diligence, and not a brand-specific investment recommendation.

Future private functionality belongs in a separate private system. Approved generic public components may be reused there; private functionality must never synchronize back automatically.
