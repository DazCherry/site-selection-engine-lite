# Development rules

Read docs/PUBLIC_PRIVATE_BOUNDARY.md before changes. Classify every material capability before implementation. Default uncertain content to PRIVATE RESERVED. Never copy confidential reference files, private methods, customer examples, secrets or personal paths into this project.

Build a deliberately generic independent model. Unknown remains unknown. Use provider adapters, explicit provenance, versioned public calculations and synthetic fixtures. Verify public provider terms before integration.

Each material capability requires implementation, unit and integration tests, independent calculation or invariant checks, adversarial review, fixes, regression, end-to-end validation, documentation and a passing checkpoint before the next capability. Never claim unexecuted tests passed.

Keep decisions in docs/ADR and actual work in docs/DEVELOPMENT_LOG.md. Scan publication contents and history before public pushes. Do not declare completion until every requested definition-of-done gate passes.

## SiteBuddy distribution phase

Use SiteBuddy as the public name, retain the existing repository and v0.1.0 traceability, and freeze the three-dimension model. Read the distribution classification in docs/PUBLIC_PRIVATE_BOUNDARY.md before new capabilities. Changes belong on a non-production branch until local, clean-environment, privacy/security/IP, end-to-end and staging gates pass. The owner selected Netlify; do not publish this phase to the prototype Sites deployment. No community posts, domains, billing, Paid features or Private Engine features are authorized. Validate destination receipt for telemetry and forms; firing a request is not acceptance. Run production smoke after promotion and roll back material failures.
