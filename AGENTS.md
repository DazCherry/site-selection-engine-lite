# Development rules

For every material production incident, follow [the incident protocol](docs/PRODUCTION_INCIDENT_PROTOCOL.md). A single successful example never closes an incident. The reliability/owner-operations phase must preserve the frozen scoring model. Do not activate any new Google API, email account, billing, sender DNS or credentials without explicit owner authorization, including free tiers. Complete independent implementation and mocked validation before escalating. Provider acceptance is not verified inbox receipt.

Read docs/PUBLIC_PRIVATE_BOUNDARY.md before changes. Classify every material capability before implementation. Default uncertain content to PRIVATE RESERVED. Never copy confidential reference files, private methods, customer examples, secrets or personal paths into this project.

Build a deliberately generic independent model. Unknown remains unknown. Use provider adapters, explicit provenance, versioned public calculations and synthetic fixtures. Verify public provider terms before integration.

Each material capability requires implementation, unit and integration tests, independent calculation or invariant checks, adversarial review, fixes, regression, end-to-end validation, documentation and a passing checkpoint before the next capability. Never claim unexecuted tests passed.

Keep decisions in docs/ADR and actual work in docs/DEVELOPMENT_LOG.md. Scan publication contents and history before public pushes. Do not declare completion until every requested definition-of-done gate passes.

## SiteBuddy distribution phase

Use SiteBuddy as the public name, retain the existing repository and v0.1.0 traceability, and freeze the three-dimension model. Read the distribution classification in docs/PUBLIC_PRIVATE_BOUNDARY.md before new capabilities. Changes belong on a non-production branch until local, clean-environment, privacy/security/IP, end-to-end and staging gates pass. The owner selected Netlify; do not publish this phase to the prototype Sites deployment. No community posts, domains, billing, Paid features or Private Engine features are authorized. Validate destination receipt for telemetry and forms; firing a request is not acceptance. Run production smoke after promotion and roll back material failures.

## Authorization continuity and incident evidence

Honor explicit authorization already supplied in the current task. Missing tool approval is not owner refusal. If automated review blocks an action, record the exact action/reason and inspect whether a narrower verified path is within existing authorization before asking again. Separate provider-specific sensitive transmissions: a Photon lookup does not authorize a second provider. Never use unrelated successful addresses to close the reported case. The current owner approved Resend Free with a single server-configured owner recipient, no payment method, overages, recharge, upgrades or visitor mail, and preparation of a dedicated sending subdomain; identity, actual DNS records and scoped credentials still require their respective gates. Google billing remains unauthorized. Keep approval-specific personal details outside this public record.

For address-provider recovery, independently verify candidate properties and retain all sample outcomes. Maximum confidence, rooftop labels and forward/reverse agreement cannot close a wrong-building finding. Never add a real-address exception to force acceptance. Keep candidate frontend activation disconnected until the location-quality gate passes; preserve the last validated production version.
